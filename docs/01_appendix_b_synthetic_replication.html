附录 B 合成实验：E2E 决策学习的可复现练习

本笔记本先复现论文附录 B 的合成数据机制和三类方法比较：事后最优标签（OPT）、端到端线性决策模型（E2E）、以及两种“先预测后优化”（PTO）基线。目标是学习动态规划标签、决策损失与时间序列实验设计。

复现边界：需求/交期生成机制、参数和方法结构依据论文附录 B。作者数据包和原始 JD 数据当前不可用；论文未完整公开随机种子及全部实现细节。本笔记本因此报告可复查的合成实验结果，不声称逐位重现论文表 5–7。为了让单次订单决策可独立评估，本教学实现将每个复核时点作为独立情景，并将初始库存设为 0；完整的多周期库存状态耦合和 M5 扩展放在后续阶段。

1. 研究问题与方法

研究问题：当需求和供应商交期都不确定时，直接学习订货量，是否能比先分别预测需求/交期再套用订货规则，更好地降低库存成本？

附录 B 的生成式为：

  • 每个决策样本有四个独立特征 x1, x2, z1, z2，均匀取自 {1, 2, 3, 4}。
  • 日需求 d_t = x1 + x2 + ε_t，其中 ε_t ~ Normal(0, σ_d²)。
  • 交期 L = z1 + z2 + ξ；ξ 取 -1, 0, 1，P(ξ=0)=p0，其余概率均分给 -1 与 +1。
  • 复核周期 R=5，成本参数 h=0.1, b=0.9，所以缺货单位成本是持有单位成本的 9 倍。保护期长度按 L + ceil(bR/(b+h)) 构造。
  • 事后标签按论文定理形式计算：a* = max(累计保护期需求 - 初始库存, 0)。

E2E 直接回归 a*；PTO1 用 KNN 估计保护期累计需求的条件分布并取 b/(b+h) 分位数；PTO2 分别回归日需求和交期，再代入保护期订货规则。OPT 是利用该测试情景未来实现值按论文标签规则算出的事后参照，不可在下单时使用；由于本教学实现简化了多周期状态，不把它宣称为完整库存系统的严格成本下界。

2. 先检查理论标签的成本逻辑

对一个确定的库存覆盖区间，公式中的持有成本和缺货成本是分段线性的。下面用小型整数例子，将论文阈值规则与穷举搜索得到的最低成本订货量对照，检查实现中的符号、正部函数和临界分位点。

def interval_cost(order_qty, daily_demand, initial_inventory, h, b):
    stock = float(initial_inventory) + float(order_qty)
    total = 0.0
    for demand in daily_demand:
        stock -= float(demand)
        total += h * max(stock, 0.0) + b * max(-stock, 0.0)
    return total

def theorem_order_label(daily_demand, initial_inventory, h, b):
    n_days = len(daily_demand)
    threshold_day = math.ceil((b / (b + h)) * n_days)
    cumulative = float(np.sum(daily_demand[:threshold_day]))
    return max(cumulative - float(initial_inventory), 0.0)

def brute_force_integer_order(daily_demand, initial_inventory, h, b):
    upper = max(0, int(math.ceil(np.sum(daily_demand) + abs(initial_inventory) + 5)))
    candidates = np.arange(upper + 1, dtype=float)
    costs = np.array([interval_cost(q, daily_demand, initial_inventory, h, b) for q in candidates])
    return float(candidates[np.argmin(costs)]), float(costs.min())

3. 生成附录 B 风格的合成订单情景

每个 SKU 在每个复核周期产生一个独立的决策情景。为与论文明确参数对齐，默认 a1=a2=b1=b2=1。为了让各方法在同一批情景上公平比较，先生成测试情景中的整段未来需求；这些未来值只用于构造训练标签和事后成本，不作为模型输入。

def generate_scenarios(seed, horizon_days, sigma_d2=1.0, p0=1/3, n_skus=N_SKUS, review_period=R):
    rng = np.random.default_rng(seed)
    n_reviews = horizon_days // review_period
    if horizon_days % review_period != 0:
        raise ValueError("horizon_days 必须是 review_period 的整数倍")
    rows = []
    for sku in range(n_skus):
        for review_idx in range(n_reviews):
            x1, x2, z1, z2 = rng.integers(1, 5, size=4)
            xi = rng.choice(np.array([-1, 0, 1]), p=np.array([(1-p0)/2, p0, (1-p0)/2]))
            lead_time = int(z1 + z2 + xi)
            if lead_time <= 0:
                raise ValueError("交期必须为正")
            protection_days = lead_time + COVER_DAYS
            mean_daily_demand = float(x1 + x2)
            daily_demand = mean_daily_demand + rng.normal(0.0, math.sqrt(sigma_d2), size=protection_days)
            initial_inventory = 0.0
            oracle_order = max(float(daily_demand.sum()) - initial_inventory, 0.0)
            rows.append({
                "sku": sku, "review_idx": review_idx, "x1": int(x1), "x2": int(x2),
                "z1": int(z1), "z2": int(z2), "xi": int(xi), "lead_time": lead_time,
                "protection_days": protection_days, "mean_daily_demand": mean_daily_demand,
                "realized_daily_average": float(daily_demand.mean()),
                "initial_inventory": initial_inventory, "oracle_order": oracle_order,
                "total_protection_demand": float(daily_demand.sum()),
                "daily_demand": daily_demand.astype(float),
            })
    return pd.DataFrame(rows)

4. 拟合 E2E 与 PTO 对照方法

为了隔离“直接学习决策”与“分别预测再优化”的差异，三种方法使用相同训练 SKU 和相同测试情景。训练/测试按 SKU 分组，避免同一个 SKU 的订单情景同时进入训练集和测试集。论文没有在附录 B 明确给出这个切分细节，因此这里把 80/20 分组切分作为显式复现约定。

def ols_fit(features, target, intercept=True):
    x = np.asarray(features, dtype=float)
    y = np.asarray(target, dtype=float)
    if intercept:
        x = np.column_stack([np.ones(len(x)), x])
    return np.linalg.lstsq(x, y, rcond=None)[0]

def ols_predict(features, beta, intercept=True):
    x = np.asarray(features, dtype=float)
    if intercept:
        x = np.column_stack([np.ones(len(x)), x])
    return x @ beta

def fit_and_predict_methods(data, train_skus=TRAIN_SKUS, k=K_KNN):
    train = data[data.sku < train_skus].reset_index(drop=True)
    test = data[data.sku >= train_skus].reset_index(drop=True)
    covariates = ["x1", "x2", "z1", "z2"]
    x_train = train[covariates].to_numpy(dtype=float)
    x_test = test[covariates].to_numpy(dtype=float)

    # E2E：直接拟合事后最优订货标签，含需求-交期交互项。
    e2e_train = np.column_stack([
        train.x1, train.x2, train.x1*train.z1, train.x1*train.z2,
        train.x2*train.z1, train.x2*train.z2,
    ])
    e2e_test = np.column_stack([
        test.x1, test.x2, test.x1*test.z1, test.x1*test.z2,
        test.x2*test.z1, test.x2*test.z2,
    ])
    beta_e2e = ols_fit(e2e_train, train.oracle_order, intercept=False)
    pred_e2e = np.maximum(ols_predict(e2e_test, beta_e2e, intercept=False), 0.0)

    # PTO2：点预测日需求与交期，再按 protection_days 规则订货。
    demand_features_train = train[["x1", "x2"]].to_numpy(dtype=float)
    demand_features_test = test[["x1", "x2"]].to_numpy(dtype=float)
    beta_demand = ols_fit(demand_features_train, train.realized_daily_average, intercept=True)
    pred_daily_demand = np.maximum(ols_predict(demand_features_test, beta_demand, intercept=True), 0.0)
    lead_features_train = train[["z1", "z2"]].to_numpy(dtype=float)
    lead_features_test = test[["z1", "z2"]].to_numpy(dtype=float)
    beta_lead = ols_fit(lead_features_train, train.lead_time, intercept=True)
    pred_lead = np.maximum(ols_predict(lead_features_test, beta_lead, intercept=True), 1.0)
    pred_pto2 = np.maximum(
        pred_daily_demand * (pred_lead + COVER_DAYS) - test.initial_inventory.to_numpy(dtype=float), 0.0
    )

    # PTO1：KNN 近邻上的保护期累计需求经验分布，再取临界分位数。
    scale = x_train.std(axis=0)
    scale[scale == 0] = 1.0
    standardized_train = (x_train - x_train.mean(axis=0)) / scale
    standardized_test = (x_test - x_train.mean(axis=0)) / scale
    train_total = train.total_protection_demand.to_numpy(dtype=float)
    pred_pto1 = np.empty(len(test), dtype=float)
    for i, row in enumerate(standardized_test):
        distances = np.sum((standardized_train - row) ** 2, axis=1)
        nearest = np.argpartition(distances, min(k-1, len(distances)-1))[:min(k, len(distances))]
        demand_quantile = np.quantile(train_total[nearest], CRITICAL_RATIO)
        pred_pto1[i] = max(float(demand_quantile) - float(test.initial_inventory.iloc[i]), 0.0)

    predictions = {
        "OPT (oracle)": test.oracle_order.to_numpy(dtype=float),
        "E2E linear": pred_e2e,
        "PTO1 KNN quantile": pred_pto1,
        "PTO2 point forecast": pred_pto2,
    }
    diagnostics = {
        "test_demand_MAE": float(np.mean(np.abs(pred_daily_demand - test.realized_daily_average.to_numpy(dtype=float)))),
        "test_lead_time_MAE": float(np.mean(np.abs(pred_lead - test.lead_time.to_numpy(dtype=float)))),
    }
    return test, predictions, diagnostics

5. 用同一组真实情景计算库存成本

每个订单情景中，订货在随机交期后到达；到货前的未满足需求形成欠交，到货后先用到货量抵消欠交，再满足当日需求。每天分别累计持有成本与缺货成本。OPT 使用未来实现值计算订货标签，作为 oracle 下界参考；可部署的方法只能使用特征做预测。

In [5]
def simulate_episode_cost(daily_demand, lead_time, order_qty, h=HOLDING_COST, b=STOCKOUT_COST):
    stock = 0.0
    holding = 0.0
    stockout = 0.0
    for day, demand in enumerate(daily_demand):
        if day == int(lead_time):
            stock += float(order_qty)
        stock -= float(demand)
        holding += h * max(stock, 0.0)
        stockout += b * max(-stock, 0.0)
    return holding, stockout, holding + stockout

def evaluate_horizon(seed, horizon_days, sigma_d2=1.0, p0=1/3):
    data = generate_scenarios(seed, horizon_days=horizon_days, sigma_d2=sigma_d2, p0=p0)
    test, predictions, diagnostics = fit_and_predict_methods(data)
    cost_rows = []
    for method, orders in predictions.items():
        for i, row in test.iterrows():
            holding, stockout, total = simulate_episode_cost(
                row.daily_demand, row.lead_time, orders[i]
            )
            cost_rows.append({"method": method, "sku": int(row.sku), "holding": holding, "stockout": stockout, "total": total})
    per_sku = pd.DataFrame(cost_rows).groupby(["method", "sku"], as_index=False)[["holding", "stockout", "total"]].sum()
    summary = per_sku.groupby("method")[["holding", "stockout", "total"]].mean().reset_index()
    summary["horizon_days"] = horizon_days
    summary["seed"] = seed
    summary["sigma_d2"] = sigma_d2
    summary["p0"] = p0
    return summary, diagnostics

读结果时先看三件事：

  1. 成本而非只看预测误差：PTO2 的需求/交期 MAE 不直接等于订货决策质量。
  2. oracle 的作用：OPT 使用未来实现值生成事后标签，只是参考，不是可部署预测器，也不在本简化评估中保证为严格成本下界。
  3. 随机性：比较 10 个种子的均值和离散程度；不要只挑一个让 E2E 表现最好的种子。

本实现与论文完整多周期库存系统的差别是：每个复核时点的订单情景独立评估，初始库存固定为零，因而未模拟相邻订单之间的库存状态传递或到货交叉。该差异会影响成本绝对值和方法排序。下一步应先补上多周期库存状态传递与到货时序，再判断与论文表 5–7 的差异；之后接入公开 M5 销量，把交期情景作为明确的模拟假设，并训练论文主文的神经网络结构。

English Version — Appendix B Synthetic Experiment

This notebook implements a reproducible synthetic exercise inspired by Appendix B. It compares an oracle benchmark (OPT), a direct end-to-end decision model (E2E), and two predict-then-optimize baselines (PTO1 and PTO2). The aim is to study decision labels, inventory costs, and experimental design; the results are not a claim of exact replication of the paper’s Tables 5–7.

Research question and data-generating process

When demand and supplier lead time are uncertain, can directly learning an order quantity reduce inventory cost more than forecasting demand and lead time separately and then applying a replenishment rule?

  • Four independent covariates x1, x2, z1, and z2 are sampled uniformly from {1, 2, 3, 4}.
  • Daily demand is d_t = x1 + x2 + ε_t, where ε_t follows a normal distribution with variance σ_d².
  • Lead time is L = z1 + z2 + ξ, where ξ is −1, 0, or 1; P(ξ=0)=p0 and the remaining probability is split equally between −1 and 1.
  • The review period is R=5 days; holding cost h=0.1 and stockout cost b=0.9. The critical ratio is b/(b+h)=0.9, and protection length follows the paper’s rule.
  • The oracle order label is a* = max(cumulative protection-period demand − initial inventory, 0).

Policies and evaluation

E2E directly regresses the oracle order label. PTO1 uses K-nearest neighbors to estimate the conditional distribution of protection-period demand and selects its 90th percentile. PTO2 forecasts demand and lead time separately, then applies the protection-period order rule. OPT uses future realized values and is unavailable at decision time; it is an oracle reference, not a deployable policy. All policies share the same training SKUs and test scenarios, with an 80/20 split by SKU to prevent the same SKU appearing in both sets.

For each test scenario, an order arrives after its realized lead time. Unmet demand accumulates as backlog; arrivals first reduce backlog, then serve current demand. Holding and stockout costs are accumulated daily. The implementation checks one small integer example against exhaustive search: both the theorem rule and grid search select order quantity 7, with cost 1.7.

Results and interpretation

Across ten random seeds, mean total cost per test SKU is:

E2E and PTO2 are nearly tied in this synthetic setup; PTO1 has higher mean cost. The setup varies demand variance and lead-time uncertainty as sensitivity exercises. These findings do not reproduce the paper’s reported E2E advantage: the demand structure is simple, and each review-period scenario is evaluated independently.

Limitations

The notebook fixes initial inventory at zero and does not propagate inventory states or overlapping arrivals across consecutive orders. These simplifications can change both cost levels and policy rankings. A full reproduction would need the paper’s complete multi-period state transitions and implementation details. The oracle uses future realizations and must not be interpreted as a deployable forecast.
